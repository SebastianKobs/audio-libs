# web-audio-engine

The edge to Web Audio: a context, and plans (`libs/audio-plan/`) built in it. A package of its own since W3b, moved out of `sound/`, which uses it as the tool does. It knows no clock and reads no globals: what it needs is passed in. It makes every Web Audio node of the sound, from a plan, and nothing else does (F6c): a strip's stages, a note's own stages, its air and gains (`NoteStages`, `libs/web-audio-synth/`, until LAY14a5c; a spot's until G0c3), and a pan pot (the test note's, until LAY14a5b) were modules it builds (`libs/web-audio-fx/`'s `BuiltModule`); only a meter's nodes, which listen, it makes on its own. The import test keeps it so (`audioNodeProblems()`, `mockup/test/module-rules.js`). Its parts (F6d): the `Engine` (`index.ts`); the kinds of node a plan names (`NodeKind`, W2a), made in the context (`nodes.ts`); a plan's nodes made, started, wired and automated (`build.ts`); a buffer's samples (`buffers.ts`); a meter (`meters.ts`); a limiter (`limiter.ts`), a node built from several, every built node in one shape (`built-node.ts`), its params in the plan's units (`param-in-units.ts`). Since LAY8a the node as built, a param in a plan's units, the limiter, a pan's and a biquad's making and the buffers are the builder's (`libs/build/web-audio/`), which takes over from it; the engine uses them from there.

```ts
import { Engine } from './index.ts';
const engine = new Engine({ AudioContext, toContext: t => t - offset });
const made = engine.build(plan, engine.at(when), dest);   // when: your clock's time; at() never maps it into the audio's past
engine.apply(made, plan.controls.release(0.5), engine.at(when));
```

| | |
|---|---|
| `new Engine({ AudioContext, toContext, latencyHint, random })` | makes the context, for low latency (`'interactive'`). iOS's audio session, whether the silent switch is heeded, is the app's to set, before it makes the engine (`tool/audio/studio/engine.ts`, W3a) |
| `audioContext`, `now()` | the context, and its time |
| `at(t)` | a time of the caller's in the context's, with `toContext`, never in its past: a sound due now starts with the next chunk the audio renders |
| `build(plan, t, destination)` | makes a plan's nodes at `t`, the context's time, into `destination`, and returns them; with no `destination`, its way out is the caller's to wire (an FX channel's input, before its chain) |
| `apply(nodes, operations, t)` | runs a handle's or a note's controls' operations on them |
| `buffer(spec)` | a buffer a plan names, made once, when it's first asked for (`libs/build/web-audio/buffers.ts`, pure, with the `random()` the engine was given): `{ noise: 2 }`, 2 s of white noise, any length; `{ impulse: 3.5 }`, a reverb's impulse response, two channels of noise darkening as it decays (`BufferSpec`, the plan's; a noise block's `'noise'` and `'breath'` its own, W2b) |
| `canPan()` | whether the context has a stereo panner: where it hasn't, a plan's panner passes the sound through, unpanned, and the mixer gives a strip no pan |
| `meter(node)` | a meter on `node` (`libs/build/web-audio/`'s `meterOn()` since LAY11a): a splitter and an analyser for each side, made as it's asked for; its `peak()`, the loudest sample of its last window of 1024, left or right, as the mixer's meters read it |
| `makeupOf(threshold, ratio)` | Web Audio's compressor adds a makeup gain of its own, which nothing turns off: for a hard knee, 0.6 × how far its curve brings full scale down, in dB (the spec's, measured in Firefox). `back`, a gain after the compressor, takes it back, so its gain alone sets how loud. The limiter's settings are the Limiter module's (`LIMITER_SETTINGS`, `libs/web-audio-fx/inserts.ts`); how it holds there is here, at the edge (`limiter.ts`) |
| a built node (`BuiltNode`, `libs/build/web-audio/built-node.ts`) | one shape for every node `build()` returns: its `input` and `output`, where its sound comes in and goes out, a Web Audio node both itself; `param(name)`, its params by the plan's names, none where it has no such one (a panner made a gain); `points` and `readings`, a limiter's, `{}` for one of Web Audio's; `node`, the Web Audio node it is, which a plan sets, starts and stops (`stop()`), none for one built from several (`paramOf(node, name)` throws where it has no such param) |
| a plan's `biquad` | its Q a plain ratio, as an EQ shows it, 0.707 flat: a lowpass's and a highpass's turned into Web Audio's dB, its level at the cutoff, set or moved (`ParamInUnits`), a bandpass's as it comes, a ratio there too; one not set Web Audio's own (`nodes.ts`, LAY6c) |
| a plan's `panner`, `limiter` | a pan, the sound made stereo before it (`channelCount` 2, explicit), so a mono sound is as loud in the middle, as the mixer's pans are, or, made with `mono: 'pan pot'`, a mono sound panned as it comes, Web Audio's own way, constant power, 3 dB down in the middle; a limiter built from several (`limiterNodes()`, `limiter.ts`): its gain (drive) into a compressor at its ceiling and the gain that takes its makeup back, its params in the plan's units (`param-in-units.ts`): its gain in dB, its ceiling in dBFS, its release in s. A sound can't be cabled into one of those. Read as Ableton's: its `points`, where a meter reads it, `in` after its gain and `out`, and its `readings`, `reduction()`, what it takes away now, in dB (`built-node.ts`) |

Tested in node, in its `test/` folder, on a stand-in for Web Audio (`test/engine.test.js`; the stand-in the builder's, `libs/build/web-audio/test/audio-stand-in.js`, reached with an engine on it, `engineOn()`, through `test/audio-stand-in.js`, which the sound's and the tool's tests run on too); what the garden builds with it is held to the recordings (`shared/test-vectors/instruments/`).
