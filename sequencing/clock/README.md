# clock

The one clock: everything asks it what time it is, and nothing reads another time source. Music time for anything, a sound, an animation synced to the beat, an event quantized to the grid. One timeline, in seconds of page time, the browser's own steady clock, which pointer events and frames already arrive on.

```js
import { Clock } from './index.ts';
const clock = new Clock({ settings: { bpm: 72, swing: 0, swingOn: '16ths', quantize: '1/16' } });   // read live: change them, and it follows
clock.start();                                   // the ticks, from a worker, so they keep going in a hidden tab
clock.onStep((i, t) => { /* the 16th i sounds at t, swung, scheduled a little ahead */ });
clock.useAudio(audioContext);                    // the grid starts with the audio, standing at its first 16th until then, and clock.audio.toContext(t) maps onto its time
const { at, on } = clock.snap(clock.now(), { nearest: true, late: 0.05 });   // a tap: when it sounds, and the step it belongs to
```

| | |
|---|---|
| `new Clock({ settings })`, `ClockSettings` | the clock (`clock.ts`, `Clock`; `index.ts` its entry), with an object it reads live: `bpm`; `swing`, 0 straight, 1 a triplet swing, 2 twice as late; `swingOn`, `'16ths'` or `'8ths'`; `quantize`, the grid `snap()` uses unless told another; `meter`. `ClockSettings`: what it reads live, its settings. Times are `Seconds`, from `libs/base/util/`. |
| `now()`, `fromEvent(ms)` | the time; a pointer event's `timeStamp` on the same timeline |
| `grid.hold(t)`, `grid.release(t)`, `grid.held`, `grid.heldAt` | a stop: the grid's place, the song position, kept while the clock's time runs on, `straightAt()` giving it from the time held on, a time before it where it was, no 16th handed out; the place the first 16th not handed out yet, those before it already played, so nothing jumps; released, going on from there, its next 16th at once; `grid.holdFrom(t)` holding it from a time on, the 16ths before it handed out, none from it |
| `grid.songTime(t)`, `grid.timeOfSong(song)`, `grid.song` | (`song-time.ts`, `SongTime`) a clock time's song time, the time the music played up to it, the grid's holds taken out, a stop's, or live play's while a recording plays back, its holds kept for the `HISTORY`, half an hour, and a minute more; within a hold, where the music stood, at the 16th it was held at, those handed out before it playing on; held now, all from it at it; never, never; and back; `grid.song` the same as a `TimeMap`, `{ toTimeline(t), fromTimeline(along) }`, for what plays along a timeline |
| `start()`, `onTick(fn(t))` | the ticks, about every 25 ms |
| `new Cues({ timeOf, handOn, lead })`: `hold(item)`, `cue(item, now)`, `tick(now)` | items held until a tick brings their time, less a `lead` where one's given, then handed on in their order, those at one time as they came (`cues.ts`): held even if its time has come, or cued, handed on at once if it has; the ticks the owner's, the clock's or a frame's. On util's `DueQueue` |
| `new GridMap({ clock })`: `placeOf(t)`, `timeOf(place)`, `stepsPerBar()`, `stepsPerBeat()` | where each 16th fell as the grid played it, heard from `onStep()` as it's scheduled, so a time long past lies where it was played after the tempo has changed, the bars lined up: straight, so a swung note lies where it sounded; in song time, so a hold, where no 16th fell, takes no room; held, the present standing still; and back (`grid-map.ts`, `HeardGrid` what it reads of the grid) |
| `onStep(fn(i, t))` | every 16th of the grid, with its swung time, `LOOKAHEAD` (0.12 s) ahead. Missed steps are skipped, and the grid keeps its place |
| `grid`: `stepDuration()`, `swingAt(i)`, `straightAt(t)`, `stepAt(t)`, `timeAt(s)`, `straightTime(s)`, `meter()`, `nextStepTime`, `nextStepNumber`, `running`, `GridSettings` | the beat grid (`beat-grid.ts`, `BeatGrid`, its swing `swing.ts`): places on it are kept straight, and played with the swing as it is now; it runs once the audio starts it, and until then stands at its first 16th, where the music will start, whatever the time. `GridSettings`: what the grid reads live: the tempo, the swing and what it swings, the time signature. |
| `grid`: `stepsPerBeat()`, `stepsPerBar()`, `beatDuration()`, `secondsOf(ticks)`, `ticksIn(seconds)`, `ticksAt(t, { straight })`, `timeOfTicks(ticks, { straight })`, `nextLine(t, steps)` | a beat and a bar by the meter, 16ths to each and a beat's length; ticks at the tempo in seconds and back; a time near now as whole ticks on the grid, swung or straight, and back; the next line of so many 16ths at or after a time, the next beat or bar |
| `PPQ`, `STEP`, `COMMON_TIME`, `barTicks(meter)`, `beatTicks(meter)`, `startsBar(i, meter)`, `Meter`, `Ticks` | time in ticks (`ticks.ts`): 96 to a quarter, 24 to a 16th, as a MIDI file's; 4/4, the time signature with none given; a bar's and a beat's length in ticks, whether a 16th starts a bar. `Meter`: a time signature, `[beats, unit]`. `Ticks`: a time in ticks, 96 to the quarter. |
| `snap(t, { straight, nearest, late, grid })`, `quantize()`, `SnapGrid`, `SnapOptions` | where a time lands on a grid (`quantizer.ts`, `GRIDS`: off, 1/4, 1/4t, 1/8, 1/8t, 1/16, 1/16t; triplets always straight): `{ at, on }`. `SnapGrid`: a grid's step in 16ths and whether it's a triplet. `SnapOptions`: a snap's options. |
| `onTempo(fn(beat))` | the beat's length told each time it changes, as a tick finds it, at the first tick too; what follows the tempo (the delays, the synced rates) follows it as it's told, none for a tick that finds it the same (`clock.ts`) |
| `useAudio(context)`; `audio`: `started()`, `toContext(t)`, `fromContext(c)`, `contextNow()`, `soonest()`, `latency()`, `settled()`, `AudioContextLike` | the edge to Web Audio (`audio-clock.ts`, `AudioClock`), from when its context is handed over: the offset to the context's time, found on every tick, never mapping into the audio's past; while the context doesn't run, its time standing still, mapping to where it stands. `AudioContextLike`: what it needs of an audio context, a browser's or a stand-in. |
| `useFake(t0)`, `advance(s, { ticks })`, `faking()` | fake mode, for tests: time moves only when told, and every tick and step of the time passed runs in order |

A frame time is the caller's. Tested in node, in its `test/` folder, on a clock and settings of its own (`test/clock.test.js`), where each 16th fell on a clock of its own (`test/grid-map.test.js`), with vectors in `shared/test-vectors/clock/`.
