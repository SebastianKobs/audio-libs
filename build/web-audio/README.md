# build/web-audio

The builder for Web Audio: handed a plan, where its sound goes and where its inputs come from, it builds it and hands back what's built, the contract's `Builder` and `Built` (`libs/build/contract/`). A package of its own since LAY8a. It reads only the plan's format and its blocks (`libs/plan/format/`, `libs/plan/blocks/`), and knows no planner, channel, desk, effect or instrument. It's the only code that makes Web Audio nodes; the old engine's (`libs/web-audio-engine/`) node as built, its params in a plan's units, its limiter, pan, biquad and buffers became this library's, and in LAY16 its audio context on a clock (`context.ts`), the engine gone.

```ts
import { WebAudioBuilder } from './index.ts';
const builder = new WebAudioBuilder({ context, beat: () => 60 / bpm });
const built = builder.build(plan, { into: context.destination, from: { in: source } });
built.set(['utility', 'level'], 0.5, { glide: 0.05 }); // a macro onto its targets
built.tempo(60 / 96);                                  // its synced delays glide there
built.set(['env', 'gate'], 1, { at: 2 });              // an envelope's curve drawn from its gate
built.placeholders; // what it couldn't make, by address
built.dispose();    // its sources stopped, its nodes disconnected
```

How a plan is built:
1. each block made by its kind (`blocks/makers.ts`), at its values and settings as they start, each input its own way in where it has several (a select's two, `BuiltNode.inputsOf()`), none for one it takes in nowhere (a select's other);
2. a block it can't make a placeholder, a gain at 1, its sound passed straight through, a source with nothing coming in silent, said by its address;
3. each composite opened, its wires made by names (`wiring.ts`): with no pool, no node of its own, its inputs the children's inputs and params they lead to, its outputs the children's outputs that lead to them; holding a pool, a gain at 1 at each of its own jacks, where its pool's copies come and go; a sound into its macro through a gain at each map's factor into what the map moves, as CV through attenuators, on through a child's macro by its own (LAY14a1c);
4. its inputs fed from where they come from, its main output into where it goes.
